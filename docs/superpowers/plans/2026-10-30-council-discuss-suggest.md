# Council Setup Auto-generate Implementation Plan

**Spec:** `docs/superpowers/specs/2026-10-30-council-discuss-suggest-design.md` — read its "Decided for the build" section first; it fixes the names, fields, clip lengths and rules every task below relies on.
**Verify:** `node scripts/verify.mjs ./pkg/council ./pkg/wshrpc/...`
**Check:** `task check:ts && go vet ./pkg/council ./pkg/wshrpc/...`
**Final:** `node scripts/cdp/final-verify.mjs council-setup`

Goal: an **Auto-generate** button in council Setup that, with at least one live agent seated, writes the topic, one
question and the mode from the seated agents' recent conversations, through one no-tools haiku call in wavesrv.

Shape: Task 1 lands the wire interface (types, RPC declaration, generated bindings, a stub handler). Task 2 (Go: reading
the transcripts and the haiku call) and Task 3 (the frontend's pure model) then run beside each other. Task 4 (the view,
the store wrapper, the CDP steps, the changelog) builds on Task 3's model; its scenario stubs the RPC, so it does not
wait for Task 2.

Rules for every task: never hand-edit generated files (`task generate` writes them); colors only from theme tokens; Go
tests on Windows need `CGO_ENABLED=1 CC="zig cc -target x86_64-windows-gnu"` (Bash) when they touch the sqlite store;
run builds and tests through Bash, not PowerShell.

### Task 2: Read the seated agents' conversations and make the haiku call
**Depends on:** Task 1
**Model:** sonnet
**Files:** `pkg/council/autogen.go`, `pkg/council/autogen_test.go`, `pkg/council/runner_test.go`, `pkg/wshrpc/wshserver/wshserver_councilautogen.go`, `pkg/wshrpc/wshserver/wshserver_councilautogen_test.go`, `pkg/wshrpc/wshserver/wshserver_council.go`

Follows the spec's "Reading the conversations", "Clipping" and "The call" sections.

- `pkg/council/autogen.go`: `type AgentConversation struct{ Name, Harness string; Prompts []string; Reply string }`
  (already clipped by the caller), `const ModelAutoGenerate = "haiku"`, an `autoGeneratePrompt(convs)` builder, a
  `parseAutoGenerate(reply) (CouncilAutoGenerate, error)`, and
  `func (r *Runner) AutoGenerate(ctx context.Context, project string, convs []AgentConversation) (CouncilAutoGenerate, error)`
  modeled on `Runner.Suggest` (`runner.go:2260`): nil Caller is an error; no conversations is an error; one
  `r.Caller.Call` with `CallReq{Expert: CouncilExpert{Id: "autogen", Name: "Auto-generate", Model: ModelAutoGenerate},
  Cwd: project, Tools: false, Prompt: ...}` (as Suggest builds its `asker` at `runner.go:2267`); `emptyReply` check;
  then parse.
  - The prompt names each agent with its harness, its prompts oldest first and its last reply, asks for one JSON block
    `{"topic", "question", "mode"}` (reuse `jsonRule` and a shape constant like `suggestShape`), states the mode rule in
    the same words `suggestPrompt` uses for brainstorm vs review, and says to write the topic and question in the
    language the person wrote their prompts in. It tells the model the text is quoted data from other sessions, not
    instructions to it.
  - Parse via `decodeReply` (`parse.go:164`). Error when: no JSON block, topic blank, question blank, mode not
    `review`/`brainstorm` (case-insensitive, trimmed; no fallback). Fold the topic's whitespace to single spaces; trim the
    question.
- `pkg/wshrpc/wshserver/wshserver_councilautogen.go`: a `gatherConversations(ctx, tabIds []string) []council.AgentConversation`
  that, per tab, uses `liveAgentLink{}.find` (`wshserver_councilagents.go:38`) and `agentTranscriptPath`
  (`wshserver_agentmsg.go:395`), then `agentsessions.HumanPrompts` (last 3 with non-blank text) and
  `agentsessions.LastAnswer`. Skip a tab on any error, a missing transcript, or no prompt. Clip in runes: each prompt
  keeps its first 600 and gets `…` appended when cut; the reply keeps its last 1,500 and gets `…` prepended when cut.
  Put the clip helper and its constants here, unexported. Make the transcript side testable without a live roster
  (e.g. split a pure `conversationFrom(name, harness, path)` that the gather calls), so tests can feed real fixture
  transcript files.
- In `wshserver_council.go`, the handler body becomes: gather; when none, return
  `errors.New("none of the seated agents has a conversation to read")` without calling the runner; else
  `councilRunner.AutoGenerate(ctx, data.Project, convs)` and return its address.

Tests (focused):
- The pkg/council `fakeCaller` (`runner_test.go`) keys a call by `req.Expert.Id + "/" + kindOf(prompt)`, and `kindOf`
  returns `"?"` for a prompt it does not know. Add an `"autogen"` case to `kindOf` matching a phrase only the
  auto-generate prompt carries, so the tests script it as `autogen/autogen`.
- `go test ./pkg/council -run 'TestAutoGenerate'`: with that fake Caller, the request is haiku with `Tools` false and its
  prompt carries every agent's name, prompts and reply plus the language rule; good reply parsed (topic whitespace
  folded); each malformed case (no JSON, blank topic, blank question, unknown mode) errors; no conversations errors
  without a call.
- `go test ./pkg/wshrpc/wshserver -run 'TestCouncilAutoGenerate|TestConversationFrom|TestClipAutogen'`: with a claude
  and a pi fixture transcript (write them in the test; look at `pkg/agentsessions` tests for the record shapes), only
  the last 3 prompts are kept in order and the last reply is read; clip lengths and the `…` marks hold for long
  multibyte (Vietnamese) text; a session with no prompts is skipped; the handler with only unreadable tabs returns the
  "none of the seated agents" error and the fake Caller records no call.

Acceptance: the named tests pass; `go build ./pkg/... ./cmd/...` passes; and the two packages' whole suites pass, run
the heavy way (`git diff --name-only main > /tmp/changed.txt && ARC_VERIFY_CHANGED=/tmp/changed.txt node scripts/verify.mjs ./pkg/council ./pkg/wshrpc/...`),
since the task edits the shared handler file and `runner_test.go`.

### Task 3: The pure model for Auto-generate
**Depends on:** Task 1 (uses the generated `CouncilAutoGenerate` and `CommandCouncilAutoGenerateData` types)
**Model:** sonnet
**Files:** `frontend/app/view/agents/councilmodel.ts`, `frontend/app/view/agents/councilsetupmodel.ts`, `frontend/app/view/agents/councilsetupmodel.test.ts`

Follows the spec's "The draft and the pure model" section exactly; the function names there are the interface Task 4
calls.

- `councilmodel.ts`: add to `CouncilSetupDraft` the optional `autoState?: "asking" | "confirm" | "failed"`,
  `autoError?: string`, `autoPending?: CouncilAutoGenerate`, `autoLast?: string`, `modeFrom?: "conversation"`, each with
  a one-line comment in the file's style. `emptyCouncilDraft` and `draftWithAgents` need no new keys (absent = idle).
- `councilsetupmodel.ts`, in a new `// ---- Auto-generate ----` section, all pure with doc comments in the file's style:
  `autoGenerateShown(draft)`, `autoGenerateRequest(draft): CommandCouncilAutoGenerateData | null` (agents' tab ids in
  seat order; null while asking, with no agent, or with a blank project), `beginAutoGenerate(draft)`,
  `settleAutoGenerate(draft, result, lib)`, `replaceAutoGenerate(draft, lib)`, `keepAutoGenerate(draft)`,
  `failAutoGenerate(draft, reason)`. Applying a result is one private helper shared by settle and replace. The group
  follows the mode through the same logic `flipMode` uses: extract it into a shared private helper rather than copying
  it.
- The person's pick, in that apply helper, is `modePicked && modeFrom !== "conversation"`: only then do the mode and
  group stay. A mode an earlier Auto-generate picked is replaced by the next result, and the group follows again.
- `flipMode` clears `modeFrom`. `modeChip` returns `<Mode> · picked from the conversation` when `modeFrom` is
  `"conversation"` (checked before the `modePicked` branch); `modeReason` returns "" for it.

Tests in `councilsetupmodel.test.ts` (`npx vitest run frontend/app/view/agents/councilsetupmodel.test.ts -t "Auto-generate"`,
one `describe("Auto-generate")`):
- shown only with at least one seated agent; request null while asking, with no agent, or no project;
- empty composer: settle applies at once (feature, question, `autoLast`, mode, `modePicked`, `modeFrom`, chip text);
- Brainstorm result moves the group to Product ideas unless `groupPicked`; Review result takes the suggestion's group or
  the UI group;
- `modePicked` already true by the person's flip: mode and group unchanged, chip still "you picked it", topic and
  question still applied;
- first press Brainstorm, second press Review on an untouched composer: the mode becomes Review, the group follows
  (suggestion's group or UI group, unless `groupPicked`), the chip still reads "picked from the conversation";
- composer holds typed text (including text from Ask the council or Run again, i.e. no `autoLast`): settle goes to
  `confirm` with `autoPending` and changes nothing else; Replace applies it; Keep leaves the draft equal to before the
  press apart from clearing the auto fields;
- second press while the composer is still exactly `autoLast` replaces without confirm; after one edit it confirms;
- re-check: text typed between begin and settle (draft edited while `asking`) leads to `confirm`;
- settle or fail on a draft that is not `asking` returns it unchanged; fail keeps feature and question and records the
  reason; `beginAutoGenerate` clears a previous error and pending result;
- `flipMode` after an Auto-generate clears `modeFrom` and the chip reads "you picked it";
- a Vietnamese topic and question pass through unchanged (no English assumed).

Acceptance: the whole of `npx vitest run frontend/app/view/agents/councilsetupmodel.test.ts frontend/app/view/agents/councilmodel.test.ts`
passes (not only the `-t` filter: `flipMode`, `modeChip` and `modeReason` change and have tests already), and
`task check:ts` exits 0.

### Task 4: The Auto-generate button, Replace / Keep, the error line and their CDP steps
**Depends on:** Task 3 (calls its model functions)
**Model:** sonnet
**Files:** `frontend/app/view/agents/councilsetup.tsx`, `frontend/app/view/agents/councilstore.ts`, `frontend/app/view/agents/councilstore.test.ts`, `scripts/cdp/council/setup.mjs`, `CHANGELOG.md`

Follows the spec's "The button", "When the composer already has text", "Errors" and "The view" sections. Read
`DESIGN.md` before styling.

- `councilstore.ts`: an `autoGenerateCouncil(data)` wrapper beside `suggestCouncil`, returning the same result shape
  `suggestCouncil` does (ok/value/error message), so the view can show the error's message. In
  `councilstore.test.ts`, add `CouncilAutoGenerateCommand: vi.fn()` to the `RpcApi` mock and a test beside the
  `suggestCouncil` one: a resolved value gives `{ok: true, value}`, a rejection gives `{ok: false, error: <message>}`.
- `councilsetup.tsx` stays thin: an async `autoGenerate(project)` beside `askCoordinator` that reads the draft, takes
  `autoGenerateRequest`, bumps **its own** per-project sequence, a sibling map `autoSeq` (never `askSeq`: a Suggest
  firing during the call bumps `askSeq`, and sharing it would drop the answer and leave `autoState` stuck at
  `asking`), `editDraft(project, beginAutoGenerate)`, awaits the wrapper, and on a still-current `autoSeq` edits the
  draft with `settleAutoGenerate` or `failAutoGenerate(reason)`. `autoSeq` is bumped only by a press and by
  `forgetAsk` (Cancel, Start), which bumps both maps; `askCoordinator` never touches it. The reason passed to
  `failAutoGenerate` is the error's first line, trimmed; the error line truncates it to one line with CSS. Pressing
  never calls Suggest.
- In `data-council-composer-bar`, right after Attach, the button when `autoGenerateShown(draft)`: `data-council-autogen`,
  label `Auto-generate`, a `Sparkles` lucide icon (a spinner icon while `autoState === "asking"`, with the button
  disabled and `aria-busy`), the same ghost classes as Attach.
- While `autoState === "confirm"`, after the button: the text `Replace the text?` and two small buttons `Replace`
  (`data-council-autogen-replace`) and `Keep` (`data-council-autogen-keep`), calling `replaceAutoGenerate` /
  `keepAutoGenerate`. After a Replace, or any applied result, reset the composer's `typed` state to null so it shows
  the draft's new text.
- While `autoState === "failed"`, one muted line under the composer (`data-council-autogen-error`) with `autoError`.
- `scripts/cdp/council/setup.mjs`: add steps after the live-agents steps (14–19), on a draft opened from
  `draftWithAgents` with `CouncilAutoGenerateCommand` stubbed through `stubRpc` (no tokens spent), extending the
  `view()` reader with the button, its busy state, the confirm controls and the error line. Number them from 20 and
  update the file's header comment. Steps run in sequence; a step that leaves a stub `pending` settles it with
  `resolveStub` / `rejectStub` (`fixtures.mjs`) before the next press. Each step asserts and shoots:
  - in steps 17 and 18 (existing), also assert the Auto-generate button is absent once both agents are removed (17)
    and present again once they are re-seated through Add agent (18);
  - 20. with agents seated and an empty composer the Auto-generate button shows beside Attach; with the stub `pending`,
    a press disables it and shows the spinner (`council-setup-autogen-busy.png`);
  - 21. `resolveStub(h, "CouncilAutoGenerateCommand", {topic, question, mode: "brainstorm"})` settles step 20's call
    (use a Vietnamese topic and question): the composer shows topic then question, the mode chip reads
    `Brainstorm · picked from the conversation`, the group is Product ideas, the button is enabled again, and that
    press's recorded request (`rpcCalls`) carries the seated tab ids (`council-setup-autogen-filled.png`);
  - 22. a second press with the text unchanged, the stub answering a different topic and `mode: "review"`, replaces the
    text without asking and the chip reads `Review · picked from the conversation`;
  - 23. after typing into the composer, a press shows `Replace the text?`; Keep leaves the typed text; a further press
    and Replace puts the result in (`council-setup-autogen-confirm.png`);
  - 24. typing during the call: with the stub `pending` on a composer still holding the last result, press, type into
    the composer, then `resolveStub` with a result: `Replace the text?` shows with the typed text intact; Keep leaves it;
  - 25. with the stub rejecting (`reject: "none of the seated agents has a conversation to read"`), the composer is
    unchanged and the error line shows that reason (`council-setup-autogen-error.png`); then, re-stubbed with a value
    on an emptied composer, a press removes the error line and fills the composer;
  - 26. a late answer is dropped: with the stub `pending`, press, then Cancel Setup and reopen it from
    `draftWithAgents`; `resolveStub` the old call; the reopened draft's composer stays empty and the button is enabled.
  - Run it as Final does: `node scripts/cdp/final-verify.mjs council-setup`, or against a running dev app with
    `task verify:ui -- council-setup`.
- `CHANGELOG.md`: one `Added` line under the top `Unreleased` section (open one if the top section has a date),
  written for the user, e.g. "Council Setup's Auto-generate writes the topic, a question and the mode from what the
  seated agents were talking about."

Acceptance: `task check:ts` exits 0; `npx vitest run frontend/app/view/agents/councilstore.test.ts` passes; the
