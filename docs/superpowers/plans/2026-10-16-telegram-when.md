# Telegram connects only when allowed and needed — implementation plan

**Verify:** `node scripts/verify.mjs ./pkg/telebot ./pkg/wconfig ./pkg/wshrpc/... ./cmd/server/...`

**Check:** `node --stack-size=4000 node_modules/typescript/lib/tsc.js --noEmit`

**Final:** `ARC_TELEGRAM_API_BASE=http://127.0.0.1:18765 node scripts/cdp/final-verify.mjs settings-telegram`

**Goal:** the Telegram bot stops long-polling `api.telegram.org` around the clock. It may connect only inside a time
the person allowed (manual "on for", a schedule with an office-hours preset, or always), and inside that time only
while a question is open. Pressing Pair connects for the code's 10 minutes in any mode, and switching it on or a new
token makes one getMe in any mode (both decided 2026-10-16, spec "When it connects").

**Spec:** `docs/superpowers/specs/2026-10-16-telegram-asks-design.md`, section "When it connects". Effort
`98752683-b111-4834-a78b-3af712f5660e`, stage `when`.

**Architecture:** a pure `pkg/telebot/allowed.go` answers "may it connect at t, until when, and when next". `bot.go`'s
`Run` gains a 2 s supervisor tick that reads the local ask registry and that answer, and starts or stops the session;
the tracker moves from the session to the bot so a reconnect keeps it. Three new settings and five new status fields
feed a reworked Settings row.

**Facts (checked 2026-10-16):**

- `Bot.Run` (`pkg/telebot/bot.go:209`) today starts a session on any poke while `Enabled` and a token are set, and the
  session (`bot.go:258`) does getMe, `GetUpdates(-1, 0)`, then `poll` + `reconcileLoop` until cancelled. The tracker is
  `session.tr` (`bot.go:195`), rebuilt per session by `newSessionTracker` (`bot.go:252`).
- `session.reconcile` (`bot.go:366`) computes `gone` and `due` from `Deps.Pending` and sends / edits.
- `tracker.due` applies `GraceMs` and skips lead-owned asks (`pkg/telebot/state.go:87-100`).
- `Deps.Settings() Settings{Enabled, ChatID}` is built in `cmd/server/main-server.go` (`startTelebot`) from
  `wconfig…Settings.TelegramEnabled/TelegramChatID` (`pkg/wconfig/settingsconfig.go:53-55`).
- Status: `telebot.Status` (`bot.go:64`) mirrored by `wshrpc.TelegramStatusData` (`pkg/wshrpc/wshrpctypes_telegram.go`),
  filled by `TelegramStatusCommand` in `pkg/wshrpc/wshserver/wshserver_telegram.go` (it adds `ChatName`);
  the row's pure model is `frontend/app/view/agents/telegrammodel.ts`, drawn by `telegramrow.tsx`; the CDP scenario
  is `settings-telegram` in `scripts/cdp/scenarios.mjs` (fake Bot API on :18765, `gotoShot: false`). The fake does
  not record `getUpdates` in `fake.calls` (it skips them), and the dev app reaches it only when started with
  `ARC_TELEGRAM_API_BASE` (the Final line sets it; `final-verify.mjs` passes `process.env` on).
- `machineLocalKeys` (`pkg/wconfig/vaultlayer.go:34`) lists the `telegram:*` keys that never sync through the vault;
  `TestVaultLayerIgnoresMachineLocalKeys` (`vaultlayer_test.go:102`) names them.
- `schema/settings.json`, `frontend/types/gotypes.d.ts` and `pkg/wconfig/metaconsts.go` are generated by
  `task generate` from `SettingsType` and the wshrpc types; never hand-edit them.
- A 401 ends the session (`session.call`, `bot.go:302`); `Run` retries a session that ended only on the next poke
  (`bot.go:231`). `TestUnauthorizedStops` wants one getMe in all.

### Task 1: Allowed-time model

**Depends on:** none

**Files:** `pkg/telebot/allowed.go`, `pkg/telebot/allowed_test.go`

```go
const (
	ModeManual   = "manual" // "" reads as this
	ModeSchedule = "schedule"
	ModeAlways   = "always"
	// OfficeHours is the schedule an unset telegram:schedule reads as.
	OfficeHours = "mon,tue,wed,thu,fri 08:00-17:30"
)

// Schedule is a weekly window in local time. End <= Start runs past midnight (End == Start is a full 24 h); Days name
// the day a window starts.
type Schedule struct {
	Days       [7]bool // indexed by time.Weekday
	Start, End int     // minutes after midnight
}

// ParseSchedule reads "<days> <HH:MM>-<HH:MM>"; days a comma list of mon…sun, case-insensitive. "" → OfficeHours.
func ParseSchedule(s string) (Schedule, error)
func (s Schedule) String() string // days in mon…sun order, lower case: ParseSchedule(OfficeHours).String() == OfficeHours

// When is the allowed-time part of the settings. The master switch is telebot.Settings.Enabled, not a field here:
// Allowed answers only for a bot that is switched on.
type When struct {
	Mode     string
	Schedule Schedule
	OnUntil  time.Time // zero = none
}

// Allowed reports whether the bot may connect at now; until is when that ends (zero = no end: always, or a schedule
// with every day and a 24 h window), next is when it starts again (zero = nothing will start it). Only until is
// meaningful when allowed, only next when not. A live OnUntil allows in every mode; until is then the later of
// OnUntil and the schedule window's end when both hold.
func (w When) Allowed(now time.Time) (allowed bool, until, next time.Time)
```

`Allowed` scans window starts and ends from the day before `now` through 8 days ahead (a wrapping window that started
yesterday covers early this morning), in `now`'s location. Daylight-saving days use wall-clock times
(`time.Date(...)`), which is what the person means by "08:00".

**Tests:** parse office hours and its `String()` round-trip; parse `"sat,sun 00:00-00:00"` (a full day); a bad string
errors (unknown day, `25:00`, no dash); `""` → office hours. `Allowed`: Wed 10:00 inside office hours → until Wed
17:30; Wed 18:00 → next Thu 08:00; Fri 18:00 → next Mon 08:00; wrap `"mon,tue,wed,thu,fri 17:30-08:00"`: Tue 07:00
allowed (Monday's window), Sat 07:00 allowed (Friday's), Sat 09:00 not, next Mon 17:30; manual with OnUntil 2 h ahead →
allowed until it; manual with an OnUntil in the past → not allowed, next zero; manual with none → not allowed, next
zero; always → allowed, until zero; schedule outside the window with a live OnUntil → allowed until OnUntil; schedule
inside the window with an OnUntil past its end → until OnUntil.

Run: `go test ./pkg/telebot -run 'TestParseSchedule|TestAllowed'` → PASS.

Commit: `feat(telebot): allowed-time model for when Telegram may connect`.

### Task 2: On-demand session, settings and status

**Depends on:** Task 1

**Files:** `pkg/telebot/bot.go`, `pkg/telebot/bot_test.go`, `pkg/telebot/state.go`, `pkg/telebot/state_test.go`, `pkg/wconfig/settingsconfig.go`, `pkg/wconfig/vaultlayer.go`, `pkg/wconfig/vaultlayer_test.go`, `pkg/wshrpc/wshrpctypes_telegram.go`, `pkg/wshrpc/wshserver/wshserver_telegram.go`, `cmd/server/main-server.go`, `schema/settings.json`, `frontend/types/gotypes.d.ts`, `pkg/wconfig/metaconsts.go`

1. **Settings** beside `TelegramChatName` (`settingsconfig.go:55`):

   ```go
   TelegramMode     string `json:"telegram:mode,omitempty"`     // when the bot may connect: "manual" (unset), "schedule", "always"
   TelegramSchedule string `json:"telegram:schedule,omitempty"` // "<days> <HH:MM>-<HH:MM>", local time; unset is office hours
   TelegramOnUntil  *int64 `json:"telegram:onuntil,omitempty"`  // manual "on for" ends at this UnixMilli; 0 or past is off
   ```

   Run `task generate` (it writes `schema/settings.json`, `metaconsts.go`'s `ConfigKey_Telegram{Mode,Schedule,OnUntil}`
   and `gotypes.d.ts`). Add the three `ConfigKey_` constants to `machineLocalKeys` (`vaultlayer.go:34`, under the
   existing telegram comment) and to the list in `TestVaultLayerIgnoresMachineLocalKeys`.
   `telebot.Settings` gains `When When`; `startTelebot` fills it (a schedule that does not parse logs once and reads as
   office hours).

2. **Clock and tracker.** `Deps` gains `Now func() time.Time` (nil → `time.Now`): the clock `When.Allowed` and the
   allowed-time-end edit read; the grace and pairing keep `time.Now`. Move `tr` (and its `mu`, and `chat`) from
   `session` to `Bot`; `newSessionTracker` runs once in `New` and again only when the paired chat changes. The session
   reads and writes the bot's tracker under the bot's mutex.

3. **Supervisor.** `Run` keeps its poke handling and adds a ticker (`Deps.Tick`). `Pair()` pokes `Run`, so a code
   connects without waiting for a tick. On each tick and poke it computes, with no network:

   - `allowed, until, next := set.When.Allowed(now)`
   - `pairing` := a live pair code (`b.pair.Pending(now)`): its own allowance, in every mode.
   - `need` := the tracker has an open ask || `tr.hasDue(pending, now)` (new in `state.go`: true when `due` would
     return an ask, without tracking anything).
   - want a session ⇔ token set && `set.Enabled` && !rejected && ((`allowed` && `need`) || `pairing`).

   `rejected` is set when a session or the validation getMe gets a 401, and cleared by a poke (any settings or token
   change, the same token too: `TestRejectedTokenIsRetriedOnPoke`). So a rejected token is not restarted by each tick.

   No session wanted while one runs: stop it once it has been unwanted for `idleLinger` (30 s, a var so tests shrink
   it), but at once when `set.Enabled` is off, the token is gone, or neither `allowed` nor `pairing` holds. Session
   wanted while none runs: start one (as today). `reconcile` moves from the session's own loop to this tick and runs
   only while a session is up; the session keeps `poll`.

4. **Validate once.** When a poke finds a new token, `Enabled` turning on, or a rejected token, and no session is
   wanted, run one `GetMe` in every mode (no polling) to set `BotName` or `LastError` (401 → `errTokenRejected` and
   `rejected`), then nothing more.

5. **Allowed time ends** with asks open (not allowed, not pairing, tracker non-empty): edit each open ask's open
   question message to `— Telegram is off until <next>` (local, `Mon 15:04` layout) or
   `— Telegram is off; answer in arcterm` when `next` is zero; forget them; stop the session. A still-pending ask is
   sent again as new once the time comes back.

6. **Status.** In `telebot.Status`, rename `Polling` to `Connected` (`json:"connected"`: the session is up and
   polling) and update `bot_test.go`'s reads (`rig.ready` waits on `Connected`). Add `Allowed bool`
   (`json:"allowed"`), `AllowedUntil int64` (`json:"alloweduntil,omitempty"`), `NextAllowed int64`
   (`json:"nextallowed,omitempty"`; both UnixMilli, 0 = none), `Open int` (`json:"open,omitempty"`, asks tracked). In
   `wshrpc.TelegramStatusData` add the same five; keep its `Polling` (`json:"polling"`), filled from `Connected`, so
   the frontend still typechecks until Task 3 drops it. Fill them in `TelegramStatusCommand`, then `task generate`.
