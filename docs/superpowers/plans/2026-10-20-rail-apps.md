# Pinned apps on the nav rail Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** up to three held services can be pinned under Radar on the nav rail, each opening as its own `app` surface
with the page filling it, the same frame Agent shows.

**Architecture:** A pure pin model and a localStorage-backed store (`railapps.ts`, `railappsstore.ts`); one new
surface key `app` with the shown service in its own atom; `AppSurface` publishes its body as the app slot, so the
shell's `AppFrames` moves the existing frame there, and the hidden Agent surface's slot stays quiet meanwhile.
`shownServices` counts the app surface, so the sleep rule holds.

**Tech Stack:** React 19 + jotai + Tailwind 4, vitest, CDP scenarios.

**Spec:** `docs/superpowers/specs/2026-10-20-rail-apps-design.md`

**Verify:** `node scripts/verify.mjs ./pkg/services/...`

**Final:** `node scripts/cdp/final-verify.mjs services-rail services-tree agent-rail-tabs surface-smoke`

The design canvas is `.superpowers/design/rail-apps/project` (boards `RailAppSurface`, `RailAppCrashed`). It is
gitignored, so the run gets it with `wsh runs start --prototype <absolute path>`. Where the spec and a board differ
(the crashed header), the spec wins: it records the person's calls of 2026-10-20.

The hand check in the Tauri app (the frame moving without a reload in WKWebView) is not a task: it is a chunk on the
effort `Held services: follow-ups`, for the person after the land.

## Global Constraints

- At most 3 pins; the refusal title is exactly `The rail holds 3 apps: unpin one first`.
- Pins live in localStorage key `apps.rail` (service ids, in the person's order). A pin whose service is gone is
  dropped and holds no place among the three; nothing prunes while `servicesAtom` is still `null` (not read yet).
- Rail placement: after Radar, behind a second divider (the same `data-nav-divider` element), before the spacer above Setup.
- Rail dot only for `retrying`/`crashed` (red, `bg-error`) and `porttaken`/`nopage` (amber, `bg-warning`); none otherwise.
- The app surface's body: `running`/`elsewhere` the page; `starting`/`sleeping` the waiting card; `crashed`,
  `retrying`, `stopped`, `porttaken`, `nopage` the card.
- The app surface's header follows the Agent header's one rule (`terminalpaneheadview.tsx`) in every state: Back,
  Forward, Reload (Windows), Home (disabled without a page), Open in the browser, then Log, Restart when `canRestart`,
  Stop when `canStop` else Start when `canStart`, and Unpin.
- Leaving the app surface: the shown service unpinned (from anywhere) and still present with a tab → Agent on its tab
  (`openTarget(model, { kind: "agent", tabId })`); gone from `tools.json`, or no id → the `agent` surface as it was.
- Opening another surface's item goes through `openTarget` (`frontend/app/view/jarvis/openref.ts`), as
  `servicespanel.tsx` `openRow` does; never set `focusIdAtom` and the surface by hand.
- Menu copy: `Pin to the rail`, `Unpin from the rail`, `Move up`, `Move down`; card button `Open its log`.
- Colors only from `@theme` tokens; status is a dot plus words; Inter everywhere.
- The terminal is never shown outside the Agent surface: `Log` opens Agent with the service selected and its Log view.
- No co-author trailer in commits.

## Review Focus

- Switching Agent → app surface → Agent with the same service: one frame element, never reloaded, and on each surface
  the frame sits over that surface's `[data-app-slot]`. The hidden Agent surface never writes the slot while `app`
  shows. Test: `services-rail` step 2 "same frame" (Task 5).
- A pinned service removed from `tools.json` while its surface shows: the pin leaves the rail and the surface falls
  back to Agent. Test: `appSurfaceService` unit tests (Task 1) and `services-rail` step 12 (Task 5).
- Unpinning the shown app lands on Agent with that service selected. Test: `services-rail` step 11 (Task 5).
- A gone pin holds no place: three live pins plus a gone one still refuse a fourth only at three live. Test:
  `withRailPin prunes a gone pin` (Task 1).
- The 56 px rail: pins show the icon alone, the label hidden, as surfaces do. Test: `services-rail` step 9 (Task 5).
- A sleeping pin opened: the waiting card, then the page. Test: `shownServices counts the app surface` (Task 2) and
  `services-rail` step 6 (Task 5).
- Five pins in localStorage from a hand edit: only the first three show. Test: `railPins keeps three` (Task 1).

### Task 1: The pin model and store

**Depends on:** none
**Files:** `frontend/app/view/agents/railapps.ts`, `frontend/app/view/agents/railapps.test.ts`, `frontend/app/view/agents/railappsstore.ts`

**Interfaces:**
- Produces in `railapps.ts` (pure, `nowMs` a parameter as in `servicesmodel.ts`):
  - `RAIL_APP_MAX = 3`; `RAIL_FULL_TITLE = "The rail holds 3 apps: unpin one first"`.
  - `parseRailPins(raw: string | null): string[]`.
  - `railPins(pins: string[], services: ServiceStatus[]): ServiceStatus[]`: the pinned services that still exist, in
    pin order, at most 3.
  - `railFull(pins: string[], services: ServiceStatus[]): boolean`: `railPins(...)` holds 3.
  - `withRailPin(pins: string[], id: string, on: boolean, services: ServiceStatus[]): string[]`: starts from the shown
    ids (`railPins(...)`), so gone ids and those past three are dropped; on appends unless present or full, off removes.
  - `movedRailPin(pins: string[], id: string, by: -1 | 1, services: ServiceStatus[]): string[]`: the same start, then
    swaps with the neighbour; unchanged at an end.
  - `railDot(s: ServiceStatus): "error" | "warning" | null`.
  - `railItemTitle(s: ServiceStatus, nowMs: number): string`: `"<name>: <row words>"`, the port (`:4321`) when the
    row words are empty (`serviceRowWords`).
  - `appSurfaceService(id: string | null, pins: string[], services: ServiceStatus[]): ServiceStatus | null`: the pinned
    service the app surface shows; `null` when the id is `null`, unpinned, or gone.
  - `appSurfaceBody(s: ServiceStatus): "page" | "waiting" | "card"` (the Global Constraints' mapping).
  - `appCard(s: ServiceStatus, nowMs: number): { title: string; line: string; action: "restart" | "start" }`, the
    words of board `RailAppCrashed`: crashed `<name> stopped after 5 crashes` / `It last exited with code <n>. Its log
    in Agent shows why.`; retrying `<name> crashed` / `It starts again in <n> s. Its log in Agent shows why.`; stopped
    `<name> is stopped` / `Start it to see its page.`; porttaken `<name> can't start` / `<port> is held by <holder or
    another program>.`; nopage `<name> shows no page` / `It is running, but nothing answered after 30 s.`. The action
    is `restart` when `canRestart`, else `start`.
- Produces in `railappsstore.ts`: `railPinsAtom` (read/write, localStorage `apps.rail`, every read and write wrapped
  in try/catch like `pinnedToolsAtom` in `toolsstore.ts:135`); `appSurfaceIdAtom: PrimitiveAtom<string | null>`;
  `setRailPinned(id: string, on: boolean): void` and `moveRailPin(id: string, by: -1 | 1): void`, which read
  `servicesAtom` and write nothing while it is `null`.

### Task 3: The app surface

**Depends on:** Task 1, Task 2
**Files:** `frontend/app/view/agents/appsurface.tsx`, `frontend/app/view/agents/apppane.tsx`, `frontend/app/view/agents/cockpitshell.tsx`, `frontend/app/view/agents/agentsurface.tsx`

**Interfaces:**
- Consumes: Task 1's model and store; `servicesAtom`, `ensureServicesFeed`, `openService`, `startService`,
  `stopService`, `restartService` (`servicesstore.ts`); `serviceHeaderLine`, `serviceRowWords`, `canStart`, `canStop`,
  `canRestart` (`servicesmodel.ts`); `appStatesAtom`, `appWaitLine`, `appHistory`, `homeApp`, `reloadAppPage`,
  `setAppView` (`appstore.ts`, `appmodel.ts`); `openTarget` (`frontend/app/view/jarvis/openref.ts`).
- Produces: `AppSlotView({ tabId, active })` exported from `apppane.tsx`; `AppPane` takes `active` and hands it on;
  `AppSurface({ model })` in `appsurface.tsx`.

**The slot.** `AppSlotView` gains `active` (default `true`): inactive, it neither measures nor publishes; and a slot
clears `appSlotAtom` on cleanup only when the atom still holds the slot object it published itself (compare by
identity), so a slot going away never clears the other surface's. `AgentSurface` renders `AppPane` with
`active={surface === "agent"}`, so the Agent surface, mounted under `display:none` while `app` shows, never writes
`{tab, rect: null}` over the app surface's slot.

**The surface.** `cockpitshell.tsx` renders `<AppSurface model={model} />` for `surface === "app"`, beside the other
unmounting surfaces. `AppSurface` calls `ensureServicesFeed()`; reads `appSurfaceService(...)`; while `servicesAtom`
is `null` it draws an empty body; when it is `null` after that, it leaves by the Global Constraints' rule (an effect,
once). A shown service with no `tabid` gets one from `openService` first. Root `data-app-surface={id}`.

Header as board `RailAppSurface` (classes copied from `terminalpaneheadview.tsx`), buttons by the Global Constraints'
rule, reusing the Agent header's data attributes (`data-app-back`, `data-app-forward`, `data-app-reload`,
`data-app-home`, `data-app-browser`) plus `data-app-log`, `data-app-restart`, `data-app-stop`, `data-app-start`,
`data-app-unpin`; the icon, the name, the project, and the state line in `data-app-surface-line`
(`serviceHeaderLine`). Unpin is `setRailPinned(id, false)`; the leave rule then opens Agent on it.

Body by `appSurfaceBody`: `page` is `<AppSlotView tabId />`; `waiting` is the waiting card (`data-app-waiting`,
`Starting <name>`, `appWaitLine`); `card` is the card over the body (`data-app-card`), board `RailAppCrashed`:
`appCard`'s title and line, the primary button (`data-app-card-action`, `Restart` or `Start`), and `Open its log`
(`data-app-open-log`).

`Log` and `Open its log`: `setAppView(tabId, "log")`, then `openTarget(model, { kind: "agent", tabId })`.
