# Pinned apps on the nav rail Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** up to three held services can be pinned under Radar on the nav rail, each opening as its own `app` surface
with the page filling it, the same frame Agent shows.

**Architecture:** A pure pin model and a localStorage-backed store (`railapps.ts`, `railappsstore.ts`); one new
surface key `app` with the shown service in its own atom; `AppSurface` publishes its body as the app slot, so the
shell's `AppFrames` moves the existing frame there. `shownServices` counts the app surface, so the sleep rule holds.

**Tech Stack:** React 19 + jotai + Tailwind 4, vitest, CDP scenarios.

**Spec:** `docs/superpowers/specs/2026-10-20-rail-apps-design.md`

**Verify:** `node scripts/verify.mjs ./pkg/services/...`

**Final:** `node scripts/cdp/final-verify.mjs services-rail`

The design canvas is `.superpowers/design/rail-apps/project` (boards `RailAppSurface`, `RailAppCrashed`). It is
gitignored, so the run gets it with `wsh runs start --prototype <absolute path>`.

## Global Constraints

- At most 3 pins; the refusal title is exactly `The rail holds 3 apps: unpin one first`.
- Pins live in localStorage key `apps.rail` (service ids, in the person's order); a pin whose service is gone is dropped.
- Rail placement: after Radar, behind a second divider (the same `data-nav-divider` element), before the spacer above Setup.
- Rail dot only for `retrying`/`crashed` (red, `bg-error`) and `porttaken`/`nopage` (amber, `bg-warning`); none otherwise.
- Menu copy: `Pin to the rail`, `Unpin from the rail`, `Move up`, `Move down`; card button `Open its log`.
- Colors only from `@theme` tokens; status is a dot plus words; Inter everywhere.
- The terminal is never shown outside the Agent surface: `Log` opens Agent with the service selected and its Log view.
- No co-author trailer in commits.

## Review Focus

- Switching Agent → app surface → Agent with the same service: one frame element, never reloaded. Test: `services-rail` step "same frame" (Task 3).
- A pinned service removed from `tools.json` while its surface is showing: the pin disappears and the surface falls back to Agent. Test: `railPins drops a removed service` (Task 1) and the fallback in `appSurfaceFallback` (Task 1).
- The 56 px rail: pins show the icon alone, the label hidden, as surfaces do. Covered by reusing `renderItem`'s `narrow` branch (Task 2).
- A sleeping pin opened: the surface shows the waiting card, then the page. Test: `shownServices counts the app surface` (Task 2) plus `services-rail` step "a sleeping pin wakes" (Task 3).
- Five pins in localStorage from a hand edit: only the first three show. Test: `railPins keeps three` (Task 1).
