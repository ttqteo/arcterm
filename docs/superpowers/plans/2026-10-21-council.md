# Council Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build the Council (spec `docs/superpowers/specs/2026-10-21-council-design.md`): a panel of expert agents that
reviews one feature in three rounds of one-shot `claude -p` calls, shown as a Reddit-style Discussion with a Summary
(ranked directions plus a matrix), started by hand from Setup or by an agent with `wsh council start`.

**Architecture:** `pkg/council` keeps one JSON file per council (like `pkg/ideastore`) and runs the rounds through a
`Caller` interface whose real implementation wraps `pkg/consult`. A `wshrpctypes_council.go` command group and a
`council:changed` event carry it to the frontend and to `wsh council`. The frontend adds a `council` centre mode on
the Agent surface (Discussion, Summary, Setup), council rows in the project tree, a palette row and an Ask the
council action on Ideas questions. Pure logic sits in `.ts` / Go files with tests beside them.

**Tech Stack:** Go (wavesrv, wsh, cobra), React 19 + jotai + Tailwind 4, vitest, CDP scenarios.

**Verify:** `node scripts/verify.mjs ./pkg/council ./pkg/consult ./pkg/tokengate ./pkg/wconfig ./pkg/wshrpc/wshserver ./skills ./cmd/wsh/cmd`
**Final:** `node scripts/cdp/final-verify.mjs council-tree council-setup council-ask council-discussion council-summary`
**Prototype:** .superpowers\design\council\project

Read before any task: `AGENTS.md` (gotchas: `task generate`, never hand-edit generated files, `task check:ts` not
`npx tsc`), `DESIGN.md` for every UI task, and the spec. The canvas boards are the visual spec: `Main.dc.html`
(Discussion, live in round 2), `Summary.dc.html`, `Setup.dc.html`, `Running.dc.html` (Discussion in round 1),
`Paused.dc.html`. Copy their copy (strings) exactly where this plan does not say otherwise; colors come from `@theme`
tokens, never the canvas hex values.

**Go tests on Windows** need the cgo prefix, or every package whose tests open the sqlite store panics:
`CGO_ENABLED=1 CC="zig cc -target x86_64-windows-gnu" go test ./pkg/x -run '<filter>'`. Every `go test` below means
with that prefix. No `-race` (the zig toolchain on Windows does not support it).

**No task starts a dev app** (`task dev`, `scripts/cdp/verify.mjs`, `final-verify.mjs`): parallel UI tasks would share
its CDP and Vite ports, WebView2 profile, store and the junctioned `src-tauri/target` / `dist/bin`, and the builds
slow the person's machine. A UI task writes its scenario steps, checks them with `node --check <file>` and
`node -e "import('./scripts/cdp/scenarios.mjs').then(m => console.log(m.SCENARIOS.filter(s => s.name.startsWith('council')).map(s => s.name)))"`
(the manifest loads and lists them), and Final runs them against its own dev app.

**No scenario spends tokens or starts a real agent.** Every action that would call a model (start, summarize, retry,
suggest, a reply to a done council, Brainstorm this) is clicked with its `RpcApi` command replaced in the page, the
way `scripts/cdp/scenarios.mjs:20070-20090` replaces `RpcApi.DagActionCommand` (import the `wshclientapi.ts` url the
page loaded, swap the method, record the call, restore it in teardown); the step asserts the recorded call.

Naming: every Go type in `pkg/council` that crosses the wire is prefixed `Council…`, so the generated TypeScript in
`frontend/types/gotypes.d.ts` does not collide with other types.

**Step 1: Types** (`types.go`), exactly:

```go
type CouncilState string

	StateRunning  CouncilState = "running"
	StateAwaiting CouncilState = "awaiting-you"
	StateDone     CouncilState = "done"
	StateNotRun   CouncilState = "not-run"
	StateStopped  CouncilState = "stopped"
	StateFailed   CouncilState = "failed"
)

type CouncilStance string

const (
	StanceAccept    CouncilStance = "accept"
	StanceChallenge CouncilStance = "challenge"
	StanceOppose    CouncilStance = "oppose"
)

const YouId = "you" // the person, as a reply author

type CouncilExpert struct {
	Id          string `json:"id"`
	Name        string `json:"name"`
	Brief       string `json:"brief"`
	Model       string `json:"model"`
	Coordinator bool   `json:"coordinator,omitempty"`
	Why         string `json:"why,omitempty"` // a suggested role's reason, Setup only
}

type CouncilGroup struct {
	Id          string   `json:"id"`
	Name        string   `json:"name"`
	Roles       []string `json:"roles"`
	Coordinator string   `json:"coordinator"`
}

type CouncilEvidence struct {
	Ref  string `json:"ref"`            // "path:line", or "screenshot:<file>#<region>"
	Weak bool   `json:"weak,omitempty"` // a claim that cites nothing
	Note string `json:"note,omitempty"` // why it is weak: `"about 3 s" has no measurement`
}

type CouncilProposal struct {
	Id        string            `json:"id"` // P1, P2, ... in arrival order
	Author    string            `json:"author"`
	Title     string            `json:"title"`
	Argument  string            `json:"argument"`
	Evidence  []CouncilEvidence `json:"evidence,omitempty"`
	Ts        int64             `json:"ts"`
	Withdrawn bool              `json:"withdrawn,omitempty"`
	Cut       bool              `json:"cut,omitempty"` // unticked by the person at the pause
}

type CouncilReply struct {
	Id         string            `json:"id"` // r1, r2, ...
	ProposalId string            `json:"proposalid"`
	ParentId   string            `json:"parentid,omitempty"` // a reply id; empty answers the proposal itself
	Author     string            `json:"author"`             // an expert id, or YouId
	Stance     CouncilStance     `json:"stance,omitempty"`
	Revised    bool              `json:"revised,omitempty"` // the author revised its own proposal here
	Text       string            `json:"text"`
	Evidence   []CouncilEvidence `json:"evidence,omitempty"`
	To         []string          `json:"to,omitempty"`    // the person's reply: the experts who answer it
	Tools      bool              `json:"tools,omitempty"` // the person's follow-up: Let them read code was on
	Answered   bool              `json:"answered,omitempty"`
	Round      int               `json:"round"` // the round it was posted in; 4+ for follow-ups after done
	Ts         int64             `json:"ts"`
}

type CouncilDirection struct {
	Rank      int                      `json:"rank"`
	Title     string                   `json:"title"`
	Reasoning string                   `json:"reasoning"`
	From      []string                 `json:"from"`    // proposal ids
	Stances   map[string]CouncilStance `json:"stances"` // expert id -> stance; the authors are left out
	Agreed    bool                     `json:"agreed"`
	IdeaId    string                   `json:"ideaid,omitempty"` // the line ideastore.Add made in the session's Ideas
}

type CouncilSummary struct {
	Text       string             `json:"text"`
	Directions []CouncilDirection `json:"directions"`
	Outcomes   map[string]string  `json:"outcomes"` // proposal id -> "Direction 1", "Merged into direction 3", "Withdrawn in round 2"
	At         int64              `json:"at"`
}

type CouncilActivity struct {
	Text       string `json:"text"`                 // `Grep "IdleSleep" in pkg/services`, `Replying to UX on P2`
	ProposalId string `json:"proposalid,omitempty"` // set while it writes a reply there
	ParentId   string `json:"parentid,omitempty"`
}

type CouncilFailure struct {
	Round int    `json:"round"`
	Error string `json:"error"`
}

type CouncilExpertStat struct {
	Ms     int64 `json:"ms"`     // time spent in this expert's calls, the running one included at its last save
	Tokens int64 `json:"tokens"` // tokens its finished calls used
	Calls  int   `json:"calls"`
}

type Council struct {
	Id               string                       `json:"id"`
	Project          string                       `json:"project"` // the project folder, the experts' cwd
	Feature          string                       `json:"feature"`
	Question         string                       `json:"question,omitempty"`
	Files            []string                     `json:"files,omitempty"`
	Screenshots      []string                     `json:"screenshots,omitempty"`
	Group            string                       `json:"group,omitempty"`
	Experts          []CouncilExpert              `json:"experts"` // the coordinator last
	PauseAfterRound1 bool                         `json:"pauseafterround1,omitempty"`
	SessionId        string                       `json:"sessionid,omitempty"` // the agent session that started it
	State            CouncilState                 `json:"state"`
	Round            int                          `json:"round"`
	Error            string                       `json:"error,omitempty"`
	Proposals        []CouncilProposal            `json:"proposals,omitempty"`
	Replies          []CouncilReply               `json:"replies,omitempty"`
	Summary          *CouncilSummary              `json:"summary,omitempty"`
	Activity         map[string]CouncilActivity   `json:"activity,omitempty"` // expert id -> what it is doing now
	Failed           map[string]CouncilFailure    `json:"failed,omitempty"`   // expert id -> its failed call
	Stats            map[string]CouncilExpertStat `json:"stats,omitempty"`    // expert id -> time and tokens so far
	Tokens           int64                        `json:"tokens"`
	Calls            int                          `json:"calls"`
	Started          int64                        `json:"started,omitempty"` // when round 1 began; 0 while not run
	Created          int64                        `json:"created"`
	Updated          int64                        `json:"updated"`
}
```

### Task 5: the runner

**Depends on:** Task 1 (uses consult.RunClaude), Task 4 (uses the prompts and parsers)

**Files:** `pkg/council/runner.go`, `pkg/council/caller.go`, `pkg/council/runner_test.go`

The runner reads a council's experts from `c.Experts` (Setup or `wsh council start` resolved them); it never looks
up a group. Every state change goes through the store's package `Update` (Task 2).

**Step 1: Interfaces.**

```go
type CallReq struct {
	Expert CouncilExpert
	Cwd    string
	Prompt string
	Tools  bool            // round 1, the Setup suggestion, a follow-up with Let them read code on
	OnTool func(text string)
}
type CallRes struct {
	Text   string
	Tokens int64
}
type Caller interface {
	Call(ctx context.Context, req CallReq) (CallRes, error)
}
```

`caller.go`: `ConsultCaller` implements it with `consult.RunClaude` (Task 1), tools `Read,Grep,Glob` when `Tools`,
none otherwise, the expert's model, and a 10-minute timeout per call. Before a round-1 call it takes a slot from
`pkg/jobqueue` the way the engine's Verify does (grep `jobqueue.` in `pkg/orchestrate`).

**Step 2: Failing tests** (`runner_test.go`) with a fake `Caller` that returns canned JSON per (expert, round) and
records every request, a temp store (`UseRootForTest`), `ideastore.UseRootForTest(t.TempDir())`
(`pkg/ideastore/ideastore.go:101`), and an `OnChange` counter:
- Start → round 1 calls every non-coordinator expert at once (all requests in flight before any returns), proposals
  get ids P1… in arrival order, then round 2, then the synthesis; the final state is `done` with a `Summary`, `Calls`
  9, `Tokens` the sum of the fakes', `Started` set, and `Stats[expert]` holding each expert's calls and tokens.
  `OnChange` fires after each save.
- `Record(c)` saves a council as `not-run` and calls nothing; `StartSaved(ctx, id)` on it runs round 1 as Start does;
  on a council in any other state it is an error.
- `PauseAfterRound1` → state `awaiting-you` after round 1; `Continue(id, cut=["P6"], question)` marks P6 `Cut`, round
  2's prompts leave it out and carry the question, and the council finishes.
- A failing expert in round 1 → `Failed[expertId] = {Round: 1, Error}`, the round goes on, the synthesis prompt names
  who was missing; `Retry(id, expertId)` reruns that expert's call in `Failed[expertId].Round` (a round-2 failure
  reruns its round-2 call) and clears the entry.
- A failing synthesis → state `failed`, `Error` set, `Failed[coordinatorId] = {Round: 3, …}`;
  `Retry(id, coordinatorId)` reruns the synthesis, as `Summarize(id)` does.
- While a call runs, `Activity[expertId]` holds the latest `OnTool` text; in round 2, `Replying to <Name> on <Pid>`
  with `ProposalId`; it is cleared when the call returns.
- `Reply(id, proposalId, parentId, text, tools)` from the person: stored with `To` = the experts in that branch (the
  proposal's author and every expert author on the path to the parent) unless the text @-mentions experts by name or
  id, then only those; `ProposalId: ""` with no parent is "Ask the whole council": `To` = every non-coordinator
  expert. A reply posted before round 2 starts is answered in round 2. A reply posted during round 2 or 3 is answered
  by an **answers pass** right after the synthesis: one call per expert in the replies' `To`, each answer a reply
  under the person's, `Answered` set; the Summary is not rerun (so its `At` is older than those answers and it reads
  Outdated). A reply after `done`, `stopped` or `failed` → a follow-up round at once, the same answers pass with
  `Tools` from the reply, state back to what it was.
- `Summarize(id)` on a done council reruns the synthesis on everything so far and replaces `Summary`; on a `stopped`
  council it runs on the rounds that finished (round 1 only included) and leaves the state `stopped`.
- `Stop(id)` cancels the in-flight calls, keeps finished rounds, state `stopped`.
- When the synthesis finishes and `SessionId` is set, each direction is added to that session's Ideas with
  `ideastore.Add(sessionId, "<title>: <reasoning's first sentence>", ideastore.KindIdea, ideastore.ByAgent,
  "Council · <feature>")` (`ideastore.go:214`) and the returned `Idea.ID` stored in the direction's `IdeaId`; a
  council without a session adds nothing; a Summarize again adds only directions whose title is new.
- `MarkStale()` turns every council left `running` (wavesrv quit mid-round) into `stopped` with
  `Error: "arcterm closed during round N"`, and leaves the others alone.
- `Suggest(ctx, project, feature, question, files)` makes one sonnet call with tools whose JSON names the files the
  experts should read, up to two extra roles with a `Why`, and the group id that fits best (one of `Groups()`'s, or
  empty); the fake's answer comes back parsed, and a group id that is not a known group comes back empty.
- `Wait(ctx, id)` returns when the state is `done`, `not-run`, `stopped`, `failed` or `awaiting-you`.

**Step 3: Implement** `Runner{Caller Caller; OnChange func(c *Council); Now func() int64}` with `Start(ctx, c)`,
`Record`, `StartSaved`, `Continue`, `Reply`, `Summarize`, `Stop`, `Retry`, `Wait`, `MarkStale`, `Suggest(ctx,
