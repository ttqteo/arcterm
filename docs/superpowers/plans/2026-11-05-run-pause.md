Task 1 lands the shared interface first: real types, constants and small helpers, plus stub functions with their
final signatures. That lets the engine, harness, run-tree, regulator, CLI and frontend tasks run beside each other.
`pkg/runpause` and `pkg/runregulator` exist from Task 1 on, so the Check can vet them in every later tree. Before
Task 1 merges, the Check fails on the base for that reason alone.

**The pause order (every task keeps it).** A pause marks before it stops anything. The top-level run's `Pause`
record, each known child run's `PausedUnder` and each dag's `PausedTs` are persisted first; only then is any agent
or command stopped. So every exit, outcome or tab-close a stop causes already reads as paused. The engine's guards
read "paused" as `jarvis.RunPaused(run)` or the run's dag having `PausedTs` set, which also covers a worker spawned
in the instant before the dag lock was taken.

### Task 2: Suspend and reopen an agent, and hold its asks
**Depends on:** Task 1
**Files:** `pkg/jarvis/runworker.go`, `pkg/jarvis/runworker_test.go`, `pkg/jarvis/runexec.go`, `pkg/jarvis/runexec_test.go`, `pkg/jarvis/pausenudge.go`, `pkg/jarvis/pausenudge_test.go`, `pkg/jarvis/attention.go`, `pkg/jarvis/attention_askprune_test.go`, `pkg/agentask/deliver.go`, `pkg/agentask/deliver_test.go`

Implements spec decisions 4 and 10.

- `SuspendRunWorker`: for each block of the worker's tab, end its process tree by destroying the controller.
  - Leave the block disarmed, so that no `ResyncController`, forced or not, starts it again. This is the durability
    `StopRunWorker` documents.
  - Keep the tab, its scrollback and the block's `agent:baseargs`. A closed tab is no error.
  - Share code with `StopRunWorker` rather than copying it.
- `ResumeRunWorker` must start a block that `SuspendRunWorker` disarmed. It re-arms the block's controller (`cmd` for
  run workers) together with the resume args, then starts it. Do not change `StopRunWorker`'s behaviour.
- `LivePendingAsks` leaves alone a pending ask whose block belongs to a run `RunPaused` reports, found through the
  block's tab owner stamp.
- `agentask` gets a `HoldAnswer func(oref string) bool` hook. When it returns true, `DeliverAnswer` claims the ask,
  keeps the answers in a held list instead of typing them into the TUI, and returns delivered.
  - Add `TakeHeldAnswers(oref string) []HeldAnswer`, each holding the question text and its answers.
  - jarvis sets the hook at init to "the block's run is paused".
- `PausedNudge` appends each held answer of the worker's block and consumes it. Text: "While you were paused, the
  person answered your question: <question> → <answer>".

Acceptance: unit tests use the existing seams (`destroyBlockController`, `persistWorkerBlockMeta`,
`startWorkerController`) and show that:
- a suspended worker's block has no controller running, and a resync does not start it;
- `ResumeRunWorker` after a suspend persists the controller and the resume args, and starts the block;
- for each runtime (claude, pi, agy, codex) the resume args come from `ResumeWorkerArgs`;
- a paused run's ask survives `LivePendingAsks`, while a gone, non-paused one is still pruned;
- an answer to a held ask is not sent as input, and appears in `PausedNudge` exactly once.

Run `go test ./pkg/jarvis -run 'Suspend|ResumeRunWorker|PausedNudge|LivePendingAsks'` and
`go test ./pkg/agentask -run 'Hold|Deliver'`.

### Task 3: Pause and resume a dag in the engine
**Depends on:** Task 1
**Files:** `pkg/orchestrate/pause.go`, `pkg/orchestrate/pause_test.go`, `pkg/orchestrate/dag.go`, `pkg/orchestrate/scheduler.go`, `pkg/orchestrate/engine.go`, `pkg/orchestrate/mergetask.go`, `pkg/orchestrate/cleanup.go`, `pkg/orchestrate/basecheck.go`, `pkg/orchestrate/plancmd.go`, `pkg/orchestrate/linkdeps.go`, `pkg/orchestrate/verify.go`, `pkg/orchestrate/final.go`, `pkg/orchestrate/outcome.go`, `pkg/orchestrate/interrupted.go`, `pkg/orchestrate/liveness.go`, `pkg/orchestrate/watchdog.go`, `pkg/orchestrate/watchdog_test.go`, `pkg/orchestrate/mutation.go`

Implements spec decisions 5, 6 and 7, and the engine half of 2. It uses `jarvis.SuspendRunWorker`,
`jarvis.ResumeRunWorker` and `jarvis.PausedNudge` through their Task 1 signatures; stub them in tests, since Task 2
builds them beside this task.

- **Status.** `RecomputeDagStatus` derives the status as today; then, while `g.PausedTs != 0` and the derived status
  is not done, it sets `paused`. Cancelled still returns first. `CancelGroup` clears `PausedTs`.
- **Setup cancel.** Add a per-dag Setup cancel registry, like `finalRuns`, covering every place a plan Setup or a
  base Setup or Check runs (`engine.go`, `basecheck.go`, `plancmd.go`, `linkdeps.go` as they apply). `PauseDag` calls
  it first, because Setup holds the dag lock for up to `SetupTimeout`.
- **`PauseDag(ctx, dagID, topRunID)`.**
  - It refuses a cancelled or done dag, and is idempotent on an already paused one.
  - Under `withDagMutation`, which waits out a merge under way, it sets `PausedTs`, recomputes the status, and marks
    every run in `DagRunIDs` except `topRunID` with `PausedUnder = topRunID`, all in one transaction.
  - After that commit it calls `stopDagVerify`, `stopDagFinal` and `releaseWorkerClaim`, then suspends the lead and
    every live session. It returns what it suspended.
- **While paused**, a guard of "the run is `RunPaused` or its dag has `PausedTs`" holds everywhere:
  - `scheduleLocked`, `AutoMergeReady` and `retryCleanupDebt` (`cleanup.go`) do nothing;
  - `watchdogStatuses` leaves paused out (test that the watchdog does not tick a paused dag);
  - a Verify or Final result that arrives for a paused dag records nothing, so tips stay `verifying` and the final
    stage stays as it was;
  - `HandleRunWorkerExit`, `HandleChildOutcome` and `HandleWorkerTabClose` (`outcome.go`) return early. A suspended
    quick run whose tab is closed stays paused, and its resume reopens it in a new tab;
  - `MarkInterruptedRuns`, `ResumeInterruptedLeads` and `cancelOrphanedDagRun` skip paused runs;
  - stall detection and `autoRetryStalled` leave the dag alone (they run inside the tick; assert it).
- **`ReopenSession`.** It resumes the session with `jarvis.ResumeRunWorker` in its tab. When the tab was closed, it
  resumes in a new tab through `resumeInNewTab`, finding the phase whose `WorkerOrefs` holds the closed tab.
- **`ResumeDag(ctx, dagID, sessions)`.**
  - It reopens each passed session with `ReopenSession` and `jarvis.PausedNudge`. A session that cannot be reopened
    is logged and left to the existing stalled retry; it does not fail the resume.
  - It sets each running task's activity baseline to now, so stall detection measures silence from the resume.
  - Then it clears `PausedTs`, calls `resumeVerify`, and calls `Schedule`.
  - It does not clear `PausedUnder`; `pkg/runpause` does that once every dag is resumed.

Acceptance: `go test ./pkg/orchestrate -run 'Pause|ResumeDag|ReopenSession|RecomputeDagStatus|Watchdog.*Paused|Exit.*Paused|Outcome.*Paused|TabClose.*Paused|Interrupted.*Paused|Cleanup.*Paused'`,
with tests that show:
- a pause during a merge waits for the merge and then pauses;
- a pause during Setup cancels Setup at once;
- the runs are marked before any suspend is called;
- a paused dag's tick spawns, merges, cleans up and retries nothing, and does not mark a task with a dead controller
  stalled;
- the Verify and Final commands are cancelled, and their cut-off results record no failure;
- a paused run's worker exit, child outcome or tab close changes no phase or task;
- resume reopens every passed session in its own session id before it clears the pause, and reruns the cut-off
  Verify;
- a resumed task with an old transcript is not stalled on the next tick;
- a done dag with `PausedTs` still reads done.

### Task 4: Pause and resume a whole run tree
**Depends on:** Task 1 (calls the signatures and helpers it fixes; Tasks 2 and 3 implement them beside this task)
**Files:** `pkg/runpause/runpause.go`, `pkg/runpause/tree.go`, `pkg/runpause/runpause_test.go`, `pkg/wshrpc/wshserver/wshserver_runs.go`

Implements spec decisions 8, 11 (the `ResumeAtBoot` body; Task 5 wires it in) and 15. Call `jarvis` and
`orchestrate` through package-level vars, so tests stub them without live tabs.

- **`Pause`.**
  - It refuses a run that is not `runqueue.TopLevel`, or is done, cancelled or already paused, with a reason the CLI
    and the UI can show.
  - It walks the tree: the run and its dag, plus every child run whose `ParentLeadORef` names a tab of a run already
    in the tree, recursively. A child orchestrator brings its own dag and lead.
  - It measures the RAM held: `orchestrate.BlockTreeBytes` of every live session block, plus
    `orchestrate.RunCommandBytes` of the tree's run ids.
  - Then, in the pause order, it writes the top-level `Pause` record with `jarvis.SetRunPause` (by, held bytes, and
    the no-flap hold) and `PausedUnder` on every child run it found. The hold is
    `NoAutoResumeUntil = now + 30 min` when `by` is `auto` and `LastResumedTs != 0`.
  - Only after that does it call `orchestrate.PauseDag(dagID, topRunID)` for each dag, and
    `jarvis.SuspendRunWorker` for each session outside a dag (a quick run's worker, a lead whose run has no dag yet,
    a child quick run).
  - Last, it stores every suspended session in `Pause.Sessions`, appends `run-paused` with `by` and `heldbytes`, and
    publishes run updates.
- **`Resume`.**
  - It refuses a run that is not paused.
  - It calls `orchestrate.ResumeDag` for each dag, with the sessions of that dag's runs, and reopens each other
    session with `orchestrate.ReopenSession` and `jarvis.PausedNudge`.
  - Then it calls `jarvis.ClearRunPause`, clears every `PausedUnder` mark, appends `run-resumed` with `by`, and
    publishes.
- **`HeldBytes`**: the same measurement, which the regulator uses to rank candidates.
- **`ResumeAtBoot`**: when `jobqueue.ReadPressure` reads warn or critical, every paused run stays paused. Otherwise
  each paused top-level run resumes with `By_Boot`. Errors are logged per run.
- **`ClearOnCancel`** (spec decision 15). For a run that was paused or carried children marked under it, it clears
  every `PausedUnder` mark under the run. It cancels each lead-spawned child run in the tree that is not done, since
  their agents are suspended and nothing would resume them. It clears `PausedTs` on each dag that the dag cancel
  does not reach. `CancelRunCommand` calls it, best effort and logged, after the existing cancel.

Acceptance: `go test ./pkg/runpause` covers:
- a child run, a task worker and a stage session are refused;
- the marks are persisted before the first suspend or `PauseDag` call;
- a quick run's one worker is suspended and its session kept;
- an orchestrator run with a lead-spawned child orchestrator pauses both dags and marks the child;
- the held RAM sums every tree;
- the run reads `paused` and counts in `runqueue.Active`;
- resume reopens each session (a closed tab included, through `ReopenSession`), and the run reads executing again
  with no marks left;
- an auto re-pause after a resume sets the 30-minute hold;
- `ResumeAtBoot` keeps runs paused under tight pressure and resumes them otherwise;
- `ClearOnCancel` leaves no `RunPaused` child behind.

### Task 5: The RAM regulator
**Depends on:** Task 1 (calls the runpause signatures it fixes)
**Files:** `pkg/runregulator/doc.go`, `pkg/runregulator/regulator.go`, `pkg/runregulator/regulator_test.go`, `pkg/runregulator/loop.go`, `pkg/runregulator/loop_test.go`, `cmd/server/main-server.go`

Implements spec decision 12, and wires in 11.

- `regulator.go`:
  - The thresholds are named constants in one block: tight for 60 s, normal for 5 min, a 60 s fresh-reading window
    between pauses, a 4 GB margin, a 1 GB floor, a 30 min no-flap hold, and standing down after 2 pauses that did
    not lower the pressure.
  - A pure `Decide(st *State, in Input) Action`. `Input` holds the pressure, free RAM, now, and the candidates. Each
    candidate carries its run id, channel id, created ts, tasks done, finalizing, mid-merge, paused, paused ts, held
    bytes and no-auto-resume-until. `Action` is none, pause(run) or resume(run).
  - The rules are exactly as decision 12.
  - **Mid-merge** means the run's dag has a task in `verifying`, or the dag is `MergeRequired` and has a task in
    `done` that is not `Merged`.
  - **Finalizing** means the dag status is `finalizing`.
- `loop.go`:
  - `Start(ctx)` ticks every 5 s, only when `runtime.GOOS` is darwin or windows, and does nothing while
    `jobqueue.Off()`.
  - Each tick reads `jobqueue.ReadPressure` and free RAM (`mem.VirtualMemoryWithContext`, as `main-server.go`
    already does for the job queue).
  - It builds candidates from the top-level runs `runqueue.Active` counts: tasks done, finalizing and mid-merge come
    from each run's dag, and held bytes from `runpause.HeldBytes`, read only for the runs being ranked.
  - It applies the action with `runpause.Pause` or `runpause.Resume` and `runpause.By_Auto`.
  - Errors are logged, never fatal, and a panic is recovered per tick.
  - The pressure, RAM and store reads go through vars, so tests script them.
- `main-server.go`: call `runpause.ResumeAtBoot` after `ResumeInterruptedLeads` and before `StartWatchdog`, and start
  the regulator after the watchdog.

Acceptance: `go test ./pkg/runregulator` covers each rule:
- no pause before 60 s of tight;
- the pick skips finalizing, mid-merge, under-1 GB and already paused runs, and orders by fewest tasks done, then
  newest;
- one pause per window;
- two pauses that did not lower the pressure stand it down until the pressure is normal;
- no resume before 5 min of normal, or without held + 4 GB free;
- resume picks the run paused longest whose hold has passed;
- Windows' unknown reading counts as normal;
- mid-merge is detected from both definitions;
- the loop does nothing while `jobqueue.Off()`.
