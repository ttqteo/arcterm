### Task 3: The mark's model and view: which reply a round started from, which turns its bar covers, the line
**Depends on:** none
**Model:** sonnet
**Files:** `frontend/app/view/agents/pairmark.ts`, `frontend/app/view/agents/pairmark.test.ts`, `frontend/app/view/agents/chatpairmark.tsx`, `frontend/app/view/agents/pairstore.ts`

Spec decision 3 and the Builder's calls on matching and on where the marks read pairs. Built standalone; Task 5 wires it into the conversation.
- `pairmark.ts` (pure), exported:
  - `replyBody(raw: string): string`: Go's `agentpair.Body` text half (drop the last `arc-pair` and the last `arc-judge` fence, trim blank lines, drop a leading `> ` line), for matching. Port its cases from `pkg/agentpair/blocks_test.go`.
  - `type PairMarkLine = { pairId: string; state: "reading" | "live" | "ended"; startTs: number; endTs: number; agreed: number; open: number }` and `type PairMarks = { lines: Map<string, PairMarkLine[]>; bars: Map<string, { pairId: string; ended: boolean }> }` (both keyed by Chat item key). Sources: `startTs` is the pair's first worker message's `ts`, `endTs` is the view's `lastts`, `agreed` and `open` are `decided.agreed.length` and `decided.open.length`.
  - `pairMarks(items: readonly ChatItem[], pairs: readonly PairView[]): PairMarks`: for each pair of this worker, the agent item whose prose (`replyBody`) equals its first worker message's `text` holds its line (several lines on one item, older pair first; a pair whose first message is not found marks nothing); its bar covers that item to the last item while the pair is not ended, and to the item matching its last worker message once ended. Where bars overlap, the newer pair (later `createdts`) owns the item. State: `reading` while the pair is not ended and no judge message exists after the first message, `live` while not ended, `ended` once `state === "ended"`.
  - `markWords(line: PairMarkLine, vi: boolean, nowMs: number): { text: string; action: string }`: the spec's words in both languages ("The judge is reading this reply · N s" / "Judge đang chấm reply này · N s", "⚖ The judge round starts here" / "⚖ Vòng judge bắt đầu ở đây", "⚖ Judge round 13:40–13:52 · 3 agreed, 0 open" / "⚖ Vòng judge 13:40–13:52 · 3 chốt, 0 còn mở"), `action` "Open pair" (live and reading) or "" (ended, the whole line opens Library).
- `chatpairmark.tsx`: `useAgentPairViews(agent: Pick<AgentVM, "id">, project: string): PairView[]` (live from `usePairs()`, ended from `usePairHistory(project)`, kept to `worker.tab === agent.id`, views from `pairViewAtom`, loaded once per id with `loadPair`); `ChatPairMarkLine({ line, vi, model, agentId, gap, arrive })` drawn like `chatjudgeline.tsx` (hairline rule, muted 12.5px, no box, spinner while reading, the seconds ticking), Open pair through `togglePairOf`, an ended line through `openAddress({ kind: "pair", pairId })`; and the bar's class helper `pairBarClass(owner)` (2px left bar, accent while live, grey when ended, colour eased; reduced motion: no transition). Colours from `@theme` tokens only. Motion as the spec says (open on the spring, state text cross-fade on the micro ease). Touch `pairstore.ts` only if a helper is missing there.
- Acceptance: `npx vitest run frontend/app/view/agents/pairmark.test.ts` covers `replyBody` (fences, quote line, a reply with neither), a live pair's line on its first reply and bar to the bottom, a reading pair, an ended pair's bar stopping at its last worker message, two rounds started on one reply (two lines, older first), overlapping bars owned by the newer pair, a first message not in the items (no mark), the line's `startTs`, `endTs`, `agreed` and `open` taken from those sources, and `markWords` in both languages for each state. `task check:ts` clean.
